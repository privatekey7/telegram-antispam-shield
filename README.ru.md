# 🛡 Telegram Anti-Spam Shield

[English](README.md) · 🌍 **Русский**

Лёгкий Telegram-бот, который **автоматически находит и удаляет спам** (на русском
и английском) с помощью маленькой встроенной ML-модели. Он быстрый, бесплатный
в работе и сделан так, чтобы **любой мог запустить его за ~10 минут** на любой
машине с Docker: сервере, Raspberry Pi, NAS или контейнерной платформе.

[![CI](https://github.com/privatekey7/telegram-antispam-shield/actions/workflows/ci.yml/badge.svg)](https://github.com/privatekey7/telegram-antispam-shield/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

---

## Что он умеет

- 🤖 Классифицирует каждое сообщение в группе как **спам** или **не спам**.
- 🗑 **Удаляет** спам автоматически (а ещё может **банить** или **мьютить** отправителя).
- 🌊 **Антифлуд:** останавливает тех, кто пишет слишком часто или повторяет одно и
  то же. Удаляет всю серию и выдаёт мут (10 мин → 1 ч → сутки за повторные нарушения).
- 🇷🇺 🇬🇧 Обучен на реальном русском и английском спаме.
- 🪶 Крошечный расход ресурсов: десятки МБ RAM, без открытых портов и базы данных.
- 📦 Готовые образы для amd64 и arm64 — или поручите установку ИИ-агенту.
- 🔌 Без внешних AI-API и без оплаты за сообщение. Модель **встроена в бота**.
- 🛟 Безопасен по умолчанию: админов не трогает, а **режим dry-run** позволяет
  посмотреть, как он работает, прежде чем он начнёт что-то удалять.

### Насколько он хорош?

Замерено на отложенной тестовой выборке из публичных спам-данных:

| Метрика | Значение |
|---|---|
| Точность (accuracy) | **97.0%** |
| ROC-AUC | **0.994** |
| Поймано спама (recall) | **93.6%** |
| Доля ложных срабатываний (удалено хорошее) | **~1.0%** |
| Размер модели | **4.2 МБ** (встроена) |

Порог принятия решения специально настроен так, чтобы **почти никогда не удалять
нормальные сообщения** — лучше пропустить часть спама, чем удалить настоящее
сообщение.

## 🚀 Установка за 10 минут

Вы сделаете три вещи: (1) создадите бота, (2) запустите его на любой удобной
машине, (3) добавите бота в группу. Выполняйте шаги по порядку.

### Шаг 1 — Создайте бота и получите токен

1. В Telegram откройте [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot` и следуйте подсказкам (придумайте имя и username).
3. BotFather выдаст **токен** вида
   `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`. **Скопируйте его** и никому
   не показывайте: у кого токен, тот управляет ботом.
4. Отправьте `/setprivacy` → выберите своего бота → нажмите **Disable**. Это
   разрешит боту видеть все сообщения в группе и проверять их на спам. *(Важно!)*

### Шаг 2 — Запустите бота

**Вариант А — поручите ИИ-агенту.** Дайте своему агенту (Claude Code, Codex,
Cursor…) доступ к машине и напишите:

> Установи Telegram-бота из https://github.com/privatekey7/telegram-antispam-shield
> по его инструкции llms-install.md.

Агент сам установит, настроит и проверит бота. От вас понадобятся только шаги
в Telegram. Инструкция: [llms-install.md](llms-install.md).

**Вариант Б — Docker вручную.** На любой постоянно включённой машине с Docker:

```bash
mkdir antispam-shield && cd antispam-shield
base=https://github.com/privatekey7/telegram-antispam-shield/releases/latest/download
curl -fsSLO "$base/compose.yaml"
curl -fsSL "$base/env.example" -o .env && chmod 600 .env
nano .env                 # впишите BOT_TOKEN=<токен из шага 1>
docker compose up -d
docker compose logs -f    # "bot_started" — бот запущен 🎉
```

**Другие способы:** `docker run`, Railway, Render, Fly.io и другие
контейнерные платформы, сборка из исходников с systemd — см.
[docs/hosting.ru.md](docs/hosting.ru.md).

> 🔒 Токен остаётся у вас: в файле `.env` (или в переменных платформы). Он не
> попадает ни в git, ни в образ.

### Шаг 3 — Добавьте бота в группу

1. Откройте вашу Telegram-**группу** → **Добавить участников** → добавьте бота.
2. Сделайте бота **администратором** как минимум с правом **Удалять сообщения**.
   *(Включите также **Блокировка пользователей**, чтобы бот мог мьютить флудеров
   и банить/мьютить спамеров.)*
3. Готово. Бот теперь удаляет спам автоматически.

**Проверка:** отправьте в группе что-нибудь спамное, например
`ЗАРАБОТОК ОТ 5000$ В ДЕНЬ! Пиши в личку` — сообщение должно удалиться за секунду.

> 🧪 Хотите сначала понаблюдать? Поставьте `ANTISPAM_DRY_RUN=true` в `.env` и
> выполните `docker compose up -d`. Бот будет только писать в лог, что он
> *удалил бы*. Верните `false`, когда убедитесь, что всё хорошо.
>
> 🔐 Имя бота публичное? Ограничьте бота своей группой через
> `ANTISPAM_ALLOWED_CHATS` — [как узнать ID группы](docs/hosting.ru.md#как-ограничить-бота-своими-чатами).

## ⚙️ Настройки

Все настройки — это **переменные окружения**: впишите их в `.env` рядом с
`compose.yaml` (или в переменные платформы), затем `docker compose up -d`.
Обязательна только `BOT_TOKEN`, у всего остального есть разумные значения по умолчанию.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | **Обязательно.** Токен от @BotFather. |
| `ANTISPAM_ACTION` | `delete` | `delete`, `ban` или `mute` для спамера. |
| `ANTISPAM_DRY_RUN` | `false` | Если `true` — только логировать, ничего не удалять. |
| `ANTISPAM_THRESHOLD` | *(из модели ≈ 0.82)* | Порог вероятности спама `0.0–1.0`. Выше = строже (меньше удалений). |
| `ANTISPAM_BLOCK_INVITE_LINKS` | `true` | Считать ссылки `t.me/+…` / `joinchat` спамом. |
| `ANTISPAM_EXEMPT_ADMINS` | `true` | Никогда не модерировать админов группы. |
| `ANTISPAM_ADMIN_CACHE_TTL` | `3600` | Сколько секунд кэшировать список админов группы. |
| `ANTISPAM_ALLOWED_CHATS` | _(все чаты)_ | ID чатов через запятую, в которых боту разрешено работать. Если задано — все остальные чаты игнорируются. **Рекомендуется, если имя бота публичное**, чтобы посторонние не добавляли его и не нагружали ваш хостинг. |
| `ANTISPAM_LEAVE_UNKNOWN_CHATS` | `false` | Если `true`, бот покидает любой чат, которого нет в `ANTISPAM_ALLOWED_CHATS`, а не просто игнорирует его. |
| `ANTISPAM_OWNER_ID` | _(любой)_ | Ваш числовой Telegram user ID. Если задан, команду `/status` в личке может использовать только владелец. Узнать ID: [@userinfobot](https://t.me/userinfobot). |
| `ANTISPAM_FLOOD_ENABLED` | `true` | Включить/выключить антифлуд. |
| `ANTISPAM_FLOOD_MAX_MESSAGES` | `6` | Флуд, если пользователь отправил **больше** стольких сообщений за окно. Альбом считается за одно. |
| `ANTISPAM_FLOOD_WINDOW_SECS` | `10` | Окно для правила частоты, секунды. |
| `ANTISPAM_FLOOD_MAX_DUPLICATES` | `3` | Флуд, если за окно повторов пришло столько сообщений с одинаковым текстом (регистр, пунктуация и растянутые буквы не важны; тексты короче 3 символов не сравниваются). |
| `ANTISPAM_FLOOD_DUPLICATE_WINDOW_SECS` | `120` | Окно для правила повторов, секунды. |
| `ANTISPAM_FLOOD_MUTE_STEPS` | `10m,1h,1d` | Длительность мута за 1-е, 2-е, 3-е… нарушение (`s`/`m`/`h`/`d`); последняя ступень повторяется. |
| `ANTISPAM_FLOOD_STRIKE_RESET_SECS` | `86400` | Счётчик нарушений сбрасывается, если столько секунд не было новых. |
| `ANTISPAM_FLOOD_NOTIFY` | `true` | Писать в чат короткое уведомление о муте. |
| `ANTISPAM_FLOOD_NOTIFY_TTL_SECS` | `30` | Через сколько секунд удалить это уведомление. |
| `RUST_LOG` | `info` | Уровень логов: `error`/`warn`/`info`/`debug`. |
| `MODEL_PATH` | *(не задано)* | Путь к своей обученной модели (для продвинутых). |

Шаблон для копирования — в файле [`.env.example`](.env.example).

## 🧠 Как это работает

```
Входящее сообщение
   │
   ├─ 0. Антифлуд  → слишком часто / один и тот же текст?                → удалить серию + мут
   │
   ├─ 1. Эвристики → инвайт-ссылки и т.п. (мгновенно, высокая точность) → спам → удалить
   │
   ├─ 2. ML-модель → вероятность спама ≥ порога?                        → спам → удалить
   │
   └─ иначе: пропустить
```

- **Антифлуд** (`src/flood.rs`) держит в памяти короткое окно последних сообщений
  каждого пользователя в каждом чате. Учитывает любые сообщения, включая стикеры
  и медиа. Счётчики нарушений хранятся в памяти и сбрасываются при перезапуске.
- **Извлечение признаков** превращает текст в хешированные словные и символьные
  n-граммы (`src/features.rs`). Символьные n-граммы дают устойчивость к
  обфускации и работают для разных языков.
- **Модель** — логистическая регрессия, хранится как бинарный файл 4 МБ, вшита в
  исполняемый файл, считается на чистом Rust (`src/model.rs`).
- **Обучение** происходит офлайн на Python (`scripts/train_model.py`). Тест
  совместимости (`tests/parity.rs`) гарантирует, что Rust-инференс совпадает с
  Python-обучением.

Ключевые архитектурные решения записаны в [`docs/adr/`](docs/adr/).

## 🛠 Разработка

```bash
# Тесты, линтер и форматтер (нужен Rust stable)
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --check

# Локальный запуск (читает BOT_TOKEN из локального .env)
cp .env.example .env   # затем впишите токен в .env
cargo run
```

Релиз: поднимите `version` в `Cargo.toml`, значение `IMAGE_TAG` по умолчанию в
`compose.yaml` (при смене минорной или мажорной версии) и перенесите `Unreleased`
в `CHANGELOG.md` под новую версию. После merge отправьте тег `vX.Y.Z`. Workflow
Release проверит, что всё совпадает, опубликует образ amd64 + arm64 в GHCR и
создаст GitHub Release. Автодеплой своего форка: [docs/auto-deploy.md](docs/auto-deploy.md).

## 🔁 Переобучение модели (опционально)

Бот поставляется с готовой моделью, поэтому это нужно только продвинутым пользователям.

```bash
pip install -r scripts/requirements.txt
python scripts/train_model.py     # скачает датасеты, обучит, запишет model/spam_model.bin
cargo test                        # parity-тест подтвердит, что Rust совпадает с новой моделью
```

Используемые датасеты:
[`alt-gnome/telegram-spam`](https://huggingface.co/datasets/alt-gnome/telegram-spam)
и [`mshenoda/spam-messages`](https://huggingface.co/datasets/mshenoda/spam-messages).

## ❓ Решение проблем

| Симптом | Что сделать |
|---|---|
| Бот ничего не удаляет | Сделайте его **админом** группы с правом **Удалять сообщения**; отключите приватность через `/setprivacy` в BotFather. |
| В логах `delete_failed` | У бота нет прав на удаление — поправьте права администратора. |
| Удалил нормальное сообщение | Поднимите `ANTISPAM_THRESHOLD` (например, `0.9`) или сообщите о примере в issue. |
| Хочу протестировать безопасно | Поставьте `ANTISPAM_DRY_RUN=true`. |
| В логах `TerminatedByOtherGetUpdates` | С этим токеном работает другая копия бота — остановите её. Копия может быть только одна. |
| Мьют не работает | Дайте право **Блокировка пользователей**; мьют работает только в супергруппах. |
